# Publishing Libraries

Devkit `ts-library` and `react-ui` packages are created with `"private": true` so internal monorepo libraries never publish accidentally. Opting a library into publication requires only native `package.json` edits followed by `devkit sync` and `make package`.

## 1. Opt In to Publication

Edit `packages/<slug>/package.json` (preserving the `tsdown` ESM output paths generated by the template):

```json
{
  "name": "@acme/design-tokens",
  "version": "0.1.0",
  "private": false,
  "type": "module",
  "files": ["dist"],
  "exports": {
    ".": {
      "types": "./dist/index.d.mts",
      "default": "./dist/index.mjs"
    },
    "./package.json": "./package.json"
  },
  "publishConfig": {
    "access": "public"
  }
}
```

For `react-ui` libraries that emit CSS via `@tsdown/css` (`dist/style.css`), keep the `./styles.css` subpath export as well:

```json
  "exports": {
    ".": {
      "types": "./dist/index.d.mts",
      "default": "./dist/index.mjs"
    },
    "./styles.css": "./dist/style.css",
    "./package.json": "./package.json"
  }
```

### Publishable Manifest Contract

Devkit enforces the following rules when `"private": false` is set on a library component:

- `role` must be `library` with profile `ts-library` or `react-ui` (`apps/*` and `react-client` must stay `"private": true`).
- `version` must be valid SemVer (for example `0.1.0` or `1.0.0-rc.1`).
- `files` must be a non-empty array containing `"dist"` (and must not include source/test paths such as `src`, `test`, or `tests`).
- `exports` must define `"."` with `"types"` listed **before** `"import"` or `"default"` (TypeScript and `publint` require `"types"` first in conditional export maps), and every target must point inside `./dist/` (except `"./package.json": "./package.json"`).
- Unscoped package names cannot set `publishConfig.access` to `"restricted"`. When publishing a scoped `@scope/pkg` publicly to `https://registry.npmjs.org/`, set `"publishConfig": { "access": "public" }` (or pass `--access public` to `npm publish`).
- Runtime dependency fields (`dependencies`, `peerDependencies`, `optionalDependencies`) cannot use `file:` links or reference any `"private": true` workspace package. If one publishable workspace library depends on another `"private": false` workspace library, declare a standard SemVer range in `dependencies` or `peerDependencies`.

After editing `packages/<slug>/package.json`, synchronize the workspace lockfile and projections:

```sh
make sync
make setup
```

## 2. Bump Package Versions

Always bump versions inside the pinned Node container so both `packages/<slug>/package.json` and root `package-lock.json` stay consistent:

```sh
npx @docouno/devkit@0.4.1 exec --component packages/ui --write -- \
  npm version 0.2.0 --no-git-tag-version
make setup
```

## 3. Build and Validate Tarballs Locally (`make package`)

Run the full validation and packaging pipeline offline:

```sh
make check
make test
make package package=ui
```

`make package` runs `build/packages/ui` (`tsdown`) and then executes `devkit-pack` inside an isolated `--network none` container (`dist/` mounted read-only, `release/` writable):

1. Verifies `private === false` and all `exports` targets exist inside the packed archive without leaking `src/`, tests, configs, or test ambient types.
2. Runs `npm pack --ignore-scripts` into a temporary staging directory.
3. Validates package structure and export conditions with `publint` (`strict: true`).
4. Validates TypeScript declaration resolution (`node16-esm` and `bundler`) with `@arethetypeswrong/core`.
5. Publishes two deterministic outputs in `packages/<slug>/release/`:
   - `<safe-name>-<version>.tgz` (for example `acme-ui-0.2.0.tgz`)
   - `package-receipt.json` (`name`, `version`, `filename`, `sha256`, `shasum`, `integrity`, `size`, `entryCount`, `publintPassed`, `attwProfile`, `attwPassed`)

If `"private": true` is still set, `make package package=<slug>` fails with an actionable hint explaining how to enable `"private": false` and run `devkit sync`.

## 4. Publish to Public npm (GitHub Actions OIDC Trusted Publishing)

Publish the verified `.tgz` artifact produced by `make package` with npm provenance — no long-lived npm token required when Trusted Publishing is configured on npmjs.com:

```yaml
jobs:
  publish:
    runs-on: ubuntu-24.04
    permissions:
      contents: read
      id-token: write
    steps:
      - uses: actions/checkout@v4
      - name: Build and verify package archive
        run: |
          make setup
          make check
          make test
          make package package=ui
      - uses: actions/setup-node@v4
        with:
          node-version: '24'
          registry-url: 'https://registry.npmjs.org'
      - name: Publish verified tarball with provenance
        run: |
          TARBALL="$(jq -r '.filename' packages/ui/release/package-receipt.json)"
          npm publish "./packages/ui/release/${TARBALL}" --provenance --access public
```

## 5. Publish to GitLab Package Registry (including Custom TLS CA)

1. Configure `publishConfig.registry` in `packages/ui/package.json` (or `@corp:registry` in root `.npmrc`):
   ```json
   "publishConfig": {
     "registry": "https://gitlab.example.com/api/v4/projects/42/packages/npm/"
   }
   ```
2. Configure root `.npmrc` with environment-variable token expansion:
   ```ini
   @corp:registry=https://gitlab.example.com/api/v4/projects/42/packages/npm/
   //gitlab.example.com/api/v4/projects/42/packages/npm/:_authToken=${GITLAB_NPM_TOKEN}
   //gitlab.example.com/api/v4/projects/42/packages/npm/:always-auth=true
   ```
3. Run `make sync` (or `npx @docouno/devkit@0.4.1 sync .`) and commit `package.json`, `.npmrc`, and `package-lock.json`.
4. In GitLab CI, map `CI_JOB_TOKEN` (or a Deploy Token) to `GITLAB_NPM_TOKEN`, pass `DEVKIT_CA_CERT` if your GitLab instance uses a private enterprise CA, build with `make package`, and publish the verified tarball through the pinned Node container (no host Node.js required):
   ```sh
   export GITLAB_NPM_TOKEN="${CI_JOB_TOKEN}"
   export DEVKIT_CA_CERT="/etc/ssl/certs/enterprise-root-ca.pem"
   make setup
   make check && make test && make package package=ui
   TARBALL="$(python3 -c 'import json; print(json.load(open("packages/ui/release/package-receipt.json"))["filename"])')"
   make exec package=ui network=bridge prepare=1 command="npm publish ./release/${TARBALL}"
   ```
