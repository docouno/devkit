# Devkit 0.6.0 migration

## Profile-scoped desktop runtime

Preview the upgrade on a branch. In a checkout without a registered Electron component, the transaction removes the managed desktop Dockerfile, seccomp profile and its two attribution files, drops the desktop recipe pin, and removes the desktop tool service from the generated Compose files. Review these changes alongside `.devkit/manifest.json` and `.devkit/runtime.sha256`. Run `make setup` and `make check` after applying the upgrade.

Use Make, the checked-in loader (`sh .devkit/runtime/devkit.sh cli doctor . --json`), or CLI `0.6.0+` with the upgraded headless checkout. An external CLI through `0.5.1` can report `Missing toolchain pin` before it reaches the accepted engine. The old `info` command can report readiness as `unknown`. See [cross-release dispatch](../upgrades.md#choosing-a-cli-for-headless-projects) for the affected commands.

Adding or registering the first Electron app installs the desktop assets from the accepted release in the registration transaction. A registered app keeps its project-owned Compose definition.

Electron apps registered with an older release keep their accepted development integration on upgrade. New registrations use `development.kind = desktop` for stand reservation and status.
