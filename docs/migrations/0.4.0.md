# Migrating to Devkit 0.4.0

Devkit `0.4.0` preserves all product-owned source files and `package.json` `scripts` during `devkit update . --to 0.4.0`. Existing `0.2.x` and `0.3.x` projects continue working without manual edits after `devkit update` and `make setup` (`npm ci` now runs with `--ignore-scripts` for third-party dependencies while running any workspace component install hooks offline without registry credentials).

The optional adjustments below let Node.js and React components created on `0.3.x` adopt the faster single-pass gates and source-level workspace HMR introduced in `0.4.0`.

## Glob Scripts and Single-Pass Checks

In `0.3.x` templates, component `package.json` scripts invoked `eslint src`, `prettier --check src`, and ran `&& npm test` inside `"check"` (duplicating test execution when running `make check && make test` in CI).

In `0.4.0`, `@docouno/env` ignores `dist/`, `release/`, and `coverage/` in ESLint and uses root globs that keep `devkit-verify` active while excluding `package.json` and `package-lock.json` from Prettier so `make fix` never invalidates the workspace dependency fingerprint.

To adopt the `0.4.0` scripts in an existing `apps/<name>/package.json` or `packages/<name>/package.json`:

```json
{
  "scripts": {
    "check": "devkit-verify && npm run format:check && npm run lint && npm run typecheck",
    "format:check": "prettier --check . \"!package.json\" \"!package-lock.json\" \"!dist/**\" \"!release/**\" \"!coverage/**\"",
    "format": "prettier --write . \"!package.json\" \"!package-lock.json\" \"!dist/**\" \"!release/**\" \"!coverage/**\"",
    "lint": "eslint --max-warnings 0 .",
    "fix": "npm run format && eslint --max-warnings 0 --fix . && npm run format"
  }
}
```

For `react-web` and `electron-react` components created on `0.3.x`, you can also remove the redundant `npm run typecheck &&` prefix from `"build"` (`"build": "vite build"` or `"build": "electron-vite build"`), since `make check` already runs `typecheck`.

If you add a separate `test/` directory with its own `tsconfig.test.json`, declare both directories and compiler configs in `package.json` so `devkit-verify` and typed ESLint cover `test/` alongside `src/`:

```json
{
  "devkit": {
    "sourceDirectories": ["src", "test"],
    "typecheckConfigs": ["tsconfig.json", "tsconfig.test.json"]
  },
  "scripts": {
    "typecheck": "tsc -p tsconfig.json --noEmit && tsc -p tsconfig.test.json --noEmit"
  }
}
```

## Design-System Vite Source Alias

Web (`react-web`) and Electron (`electron-react`) applications consuming internal `react-ui` or `ts-library` workspace packages can enable instant Vite HMR against `packages/*/src` without rebuilding `packages/*/dist` on every edit.

Update `apps/<name>/vite.config.mjs` (or the renderer plugins in `electron.vite.config.cjs`) to add `devkitWorkspaceSource` from `@docouno/env/vite`:

```js
import { devkitWorkspaceSource } from '@docouno/env/vite';
import react from '@vitejs/plugin-react';
import { defineConfig } from 'vite';

export default defineConfig({
  plugins: [devkitWorkspaceSource(), react()],
});
```

`devkitWorkspaceSource()` activates only during `vite serve` (`make dev`); `make build` continues resolving workspace packages through their compiled `exports` map in `dist/`.
