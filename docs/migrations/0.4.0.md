# Migrating to Devkit 0.4.0

Devkit `0.4.0` preserves all product-owned source files and `package.json` `scripts` during `devkit update . --to 0.4.0`. Existing `0.2.x` and `0.3.x` projects continue working without manual edits after `devkit update` and `make setup`.

The optional adjustments below let Node.js and React components created on `0.3.x` adopt the faster single-pass gates and source-level workspace HMR introduced in `0.4.0`.

## Glob Scripts and Single-Pass Checks

In `0.3.x` templates, component `package.json` scripts invoked `eslint src`, `prettier --check src`, and ran `&& npm test` inside `"check"` (duplicating test execution when running `make check && make test` in CI).

In `0.4.0`, `@docouno/env` ignores `dist/` and `release/` in ESLint and supports fast file-glob scripts that lint and format `test/` alongside `src/` without re-running tests during `make check`.

To adopt the `0.4.0` scripts in an existing `apps/<name>/package.json` or `packages/<name>/package.json`:

```json
{
  "scripts": {
    "check": "npm run typecheck && npm run lint && npm run format:check",
    "lint": "eslint \"**/*.{ts,tsx,mts,cts,js,mjs,cjs}\"",
    "format": "prettier --write \"**/*.{ts,tsx,mts,cts,js,mjs,cjs,json,css,md}\"",
    "format:check": "prettier --check \"**/*.{ts,tsx,mts,cts,js,mjs,cjs,json,css,md}\""
  }
}
```

If the component includes a `test/` directory with its own `tsconfig.test.json`, update `"typecheck"` to validate both configs:

```json
    "typecheck": "tsc -p tsconfig.json --noEmit && tsc -p tsconfig.test.json --noEmit",
```

## Design-System Vite Source Alias

Web (`react-web`) and Electron (`electron-react`) applications consuming internal `react-ui` or `ts-library` workspace packages can enable instant Vite HMR against `packages/*/src` without rebuilding `packages/*/dist` on every edit.

Update `apps/<name>/vite.config.mjs` (or renderer plugins in `electron.vite.config.cjs`) to add `devkitWorkspaceSource` from `@docouno/env/vite`:

```js
import { devkitWorkspaceSource } from '@docouno/env/vite';
import react from '@vitejs/plugin-react';
import { defineConfig } from 'vite';

export default defineConfig({
  plugins: [devkitWorkspaceSource(), react()],
});
```

`devkitWorkspaceSource()` activates only during `vite serve` (`make dev`); `make build` continues resolving workspace packages through their compiled `exports` map in `dist/`.
