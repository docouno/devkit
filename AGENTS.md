# Devkit contributor instructions

- Use the root `Makefile` for author work. `make setup` prepares the pinned toolchains. `make check` and `make test` run source checks and tests. `make fix-format` applies formatting and `make build` builds the release engine.
- Run the author gates in their pinned containers. The host needs Linux x86-64, Git, Make, Python 3, Docker and Docker Compose 5 or newer.
- Consumer Make targets are defined in `runtime/devkit.mk`. Keep project-owned files under the project's control through updates and load tools from the accepted release.
- Keep the README examples and consumer verification in sync. Use `make help` for the assembly and verification commands. `make pack` requires a clean committed source tree.
- Keep agent instruction files outside templates and release archives. Project instructions are generated by `devkit init`.
