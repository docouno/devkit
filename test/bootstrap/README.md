# Bootstrap verification

After packing two release versions, run:

```sh
bash test/verify-bootstrap.sh \
  --release .artifacts/devkit-0.2.0.tar.gz \
  --next-release .artifacts/devkit-0.2.1.tar.gz \
  --bootstrap .artifacts/devkit-0.2.0.sh
```

The default paths follow `VERSION` and its next patch. The script requires Linux,
Bash, GNU utilities, Python 3 and a local Docker daemon with Compose. Host
Node/npm/Rust commands are blocked. The bootstrap is downloaded over real
loopback HTTP, then downloads and verifies the supplied archives outside the
author checkout. Tests never rebuild or overwrite those archives.

The normal run covers selected-version init/update/recovery, accepted-version
registration and component addition, source preservation, malformed archives,
HTTP failures, process cancellation and resource limits. Safety tests include a
real 60-second timeout. `--safety-only` or `--skip-safety` selects a targeted run.
`--render-template` explicitly tests the current template before a bootstrap has
been packed; it does not verify the built bootstrap artifact.

To exercise preserved legacy releases and a real HTTP upgrade from schema 1 to
the current release, supply `--legacy-release` and `--legacy-next-release`.
For transport development before new releases exist,
`--legacy-only --render-template` selects the unchanged local 0.1.0/0.1.1
archives. A fresh checkout need not contain those historical artifacts.

Each run records command logs, source archive identities and `receipt.json`
under `.artifacts/bootstrap/<run-id>`. Successful scratch trees are removed;
failed ones remain for diagnosis. Docker assertions use exact names generated by
the invocation. No global Docker cleanup, registry configuration or host SDK
installation is performed.
